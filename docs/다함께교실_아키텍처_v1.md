# 다함께교실 — 클린 아키텍처 설계도 (2단계) v1.0

1단계 PRD의 후속 문서. 스택: **앱 React Native(Expo) \+ 웹 Next.js \+ 백엔드 Supabase(Edge Functions/Postgres/pgvector)**, 전부 TypeScript. 이 문서는 바이브코딩 도구에 붙여넣어 폴더·테이블·API를 생성하는 설계 원본이다.

---

## 1\. 설계 3원칙 (학생에게 가르칠 핵심)

1. **의존성은 안쪽으로만 흐른다.** 화면(UI)은 유스케이스를 알지만, 유스케이스는 화면을 모른다. 바깥(UI·DB·AI API)을 바꿔도 안쪽(규칙)은 안 바뀐다.  
2. **로직은 클라이언트가 아니라 서버에 둔다.** 번역·통역·LLM·RAG 호출은 전부 Supabase Edge Functions가 수행한다. 앱·웹은 "화면 \+ 서버 호출"만 한다.  
3. **비밀(API 키)은 절대 앱·웹에 두지 않는다.** 키는 Edge Functions 환경변수에만 존재한다.

## 3\. 모노레포 폴더 구조 (TypeScript 통일의 핵심)

앱·웹·백엔드가 **공통 코드(타입·도메인 규칙)를 공유**하도록 모노레포로 둔다.

dahamkke/

├── apps/

│   ├── mobile/                 \# React Native (Expo) — 1차

│   │   └── src/

│   │       ├── presentation/   \# 화면, 컴포넌트, 상태(UI 전용)

│   │       │   ├── screens/    \# MainScreen, TranslateScreen, InterpretScreen ...

│   │       │   └── components/

│   │       ├── application/     \# 유스케이스 호출 \+ 화면 상태 연결(hooks)

│   │       └── infrastructure/  \# API 클라이언트(Edge Functions 호출), 디바이스(카메라/마이크)

│   └── web/                     \# Next.js — 2차 (동일 application/infra 재사용)

│

├── packages/

│   ├── domain/                 \# ★ 안쪽 계층: 엔티티 \+ 규칙 (UI·DB 모름)

│   │   ├── entities/           \# User, Textbook, TextChunk, Persona, Dialog ...

│   │   ├── usecases/           \# TranslateText, InterpretSpeech, AskPersona ...

│   │   └── ports/              \# 인터페이스(TranslationPort, RagPort) — 구현은 바깥

│   └── shared/                 \# 공통 타입, 상수(언어 코드 6종), 검증

│

└── supabase/

    ├── functions/             \# Edge Functions(유스케이스의 서버 구현)

    │   ├── translate/

    │   ├── interpret/

    │   ├── chat-debate/

    │   ├── persona/

    │   ├── rag-ingest/        \# 교사: 교과서 등록·색인

    │   └── notice-translate/  \# 가정통신문

    └── migrations/            \# DB 스키마(SQL)

**의존성 규칙**: `presentation → application → domain` (안쪽으로만). `infrastructure`와 `supabase/functions`는 `domain/ports` 인터페이스를 **구현**한다. domain은 누구도 import하지 않는다.

## 4\. 계층별 역할 (앱 기준)

| 계층 | 하는 일 | 예 |
| :---- | :---- | :---- |
| Presentation | 화면 그리기, 사용자 입력 | `TranslateScreen.tsx` (카메라·언어선택 UI) |
| Application | "지금 무엇을 할지" 조율 | `useTranslate()` 훅이 유스케이스 호출 |
| Domain | 변하지 않는 규칙·타입 | `TranslateText` 유스케이스, `Language` 타입 |
| Infrastructure | 바깥과 통신 | `EdgeApiClient` (서버 호출), `CameraAdapter` |

핵심: **AI/DB가 Domain에 직접 안 들어온다.** Domain은 `TranslationPort` 같은 인터페이스만 알고, 실제 호출(Edge Function)은 Infrastructure가 담당. → 나중에 OpenAI를 다른 모델로 바꿔도 화면·규칙은 그대로.

## 5\. 데이터베이스 스키마 (Supabase / Postgres \+ pgvector)

\-- 확장: 벡터 검색

create extension if not exists vector;

\-- 사용자 (Supabase auth.users와 1:1 프로필)

create table profiles (

  id uuid primary key references auth.users(id),

  name text not null,

  role text not null check (role in ('student','teacher','parent')),

  native\_language text not null,           \-- 'ru','zh','vi','uz','kk','ko'

  created\_at timestamptz default now()

);

\-- 교과서 단원

create table textbooks (

  id uuid primary key default gen\_random\_uuid(),

  subject text not null,

  grade int,

  unit\_title text not null,

  owner\_id uuid references profiles(id),   \-- 등록 교사

  created\_at timestamptz default now()

);

\-- RAG 색인: 교과서 문단 \+ 임베딩

create table text\_chunks (

  id uuid primary key default gen\_random\_uuid(),

  textbook\_id uuid references textbooks(id) on delete cascade,

  content text not null,

  embedding vector(1536),                  \-- 임베딩 모델 차원에 맞춤

  chunk\_order int

);

create index on text\_chunks using ivfflat (embedding vector\_cosine\_ops);

\-- 교과서 인물 페르소나

create table personas (

  id uuid primary key default gen\_random\_uuid(),

  textbook\_id uuid references textbooks(id) on delete cascade,

  character\_name text not null,

  system\_prompt text not null              \-- 역할·말투·시대 제약

);

\-- 번역 기록(OCR/가정통신문)

create table translations (

  id uuid primary key default gen\_random\_uuid(),

  user\_id uuid references profiles(id),

  type text check (type in ('ocr','notice')),

  source\_text text,

  target\_lang text,

  result\_text text,

  created\_at timestamptz default now()

);

\-- 대화 기록(토론/인터뷰)

create table dialogs (

  id uuid primary key default gen\_random\_uuid(),

  user\_id uuid references profiles(id),

  mode text check (mode in ('debate','interview')),

  messages jsonb not null default '\[\]',    \-- \[{role, content, lang}\]

  created\_at timestamptz default now()

);

### RAG 검색 함수 (pgvector)

create or replace function match\_chunks(

  query\_embedding vector(1536), book\_id uuid, match\_count int default 4\)

returns table (content text, similarity float)

language sql stable as $$

  select content, 1 \- (embedding \<=\> query\_embedding) as similarity

  from text\_chunks

  where textbook\_id \= book\_id

  order by embedding \<=\> query\_embedding

  limit match\_count;

$$;

## 6\. 보안: RLS (행 수준 보안) — 디지털 시민성 학습 소재

alter table translations enable row level security;

alter table dialogs enable row level security;

\-- 학생은 '자기 기록'만 조회/수정

create policy "own translations" on translations

  for all using (auth.uid() \= user\_id);

create policy "own dialogs" on dialogs

  for all using (auth.uid() \= user\_id);

\-- 교과서/페르소나는 모두 읽기, 교사만 쓰기

create policy "read textbooks" on textbooks for select using (true);

create policy "teacher writes textbooks" on textbooks

  for insert with check (

    exists(select 1 from profiles p where p.id \= auth.uid() and p.role='teacher')

  );

가르칠 포인트: "로그인했다고 남의 데이터까지 보이면 안 된다" → RLS로 DB가 직접 막는다.

## 7\. Edge Functions API 명세 (앱·웹 공통 호출)

모든 요청은 `Authorization: Bearer <supabase_jwt>` 포함. 키(OpenAI/Vision)는 함수 환경변수에만.

| 메서드·경로 | 입력 | 처리 | 출력 |
| :---- | :---- | :---- | :---- |
| `POST /translate` | `{ imageBase64 | text, targetLang }` | (이미지면) Vision OCR → 번역 LLM | `{ sourceText, resultText }` |
| `POST /interpret` | `{ audioBase64, fromLang, toLang }` | STT → 번역 → TTS | `{ sourceText, resultText, audioUrl }` |
| `POST /chat-debate` | `{ topic, message, userLang, history }` | (필요시 RAG) → 토론 응답 → userLang 번역 | `{ replyKo, replyUser }` |
| `POST /persona` | `{ personaId, question, userLang, history }` | RAG로 근거 문단 검색 → 페르소나 LLM | `{ answer, sources[] }` |
| `POST /rag-ingest` | `{ textbookId, rawText }` (교사) | 문단 분할 → 임베딩 → text\_chunks 저장 | `{ chunks: n }` |
| `POST /notice-translate` | `{ imageBase64, targetLangs[] }` | OCR → 다국어 번역 \+ 핵심요약 | `{ translations, summary }` |

로봇(Reachy Mini)도 온디바이스 STT 후 **같은 `/interpret`·`/persona`** 를 호출 → 코드 재사용.

## 8\. 핵심 기능 데이터 흐름 (예: 인물 인터뷰 \+ RAG)

\[앱\] 사용자가 '흥부'에게 질문 입력(베트남어)

  → infrastructure: POST /persona { personaId, question, userLang:'vi', history }

\[Edge Function /persona\]

  1\) 질문을 임베딩 → match\_chunks(embedding, textbookId) 로 근거 문단 4개 검색

  2\) LLM 프롬프트 \= persona.system\_prompt \+ 근거문단 \+ 질문

  3\) 답변 생성(한국어) → 베트남어 병기 번역

  4\) dialogs 테이블에 기록 저장(RLS로 본인만)

  → { answer, sources:\[단원/문단\] }

\[앱\] 답변 \+ "근거: 2단원 3문단" 표시

환각 억제 포인트: **근거 문단을 프롬프트에 강제 주입**하고, 없으면 "교과서에 없는 내용은 상상"이라고 답하도록 system\_prompt에 규정.

## 9\. 구현 순서 (바이브코딩 투입 순서)

1. `supabase/migrations` — 5·6장 SQL 실행(테이블·RLS·match\_chunks).

4. `/interpret`(F2) → InterpretScreen.  
5. `/rag-ingest` \+ `/persona`(F5·F4) → 교사 등록 화면 \+ 인터뷰 화면.  
6. `/chat-debate`(F3), `/notice-translate`(F7).  
7. `apps/web`(Next.js)로 동일 호출 재사용(2차).
