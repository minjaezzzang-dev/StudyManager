# 다함께교실 (Dahamkke Classroom) — 제품 요구사항 정의서 (PRD) v1.0

온디바이스 AI 에이전트를 활용한 '학습장벽 없는 다함께 교실' 프로젝트 2026 특성화교육실천사례연구대회(영재분야) · 천안불무초등학교 정보영재 사사과정 작성: 정웅 | 대상 학생: 이서준, 황보민재, 가동현, 송재희

---

## 0\. 이 문서의 사용법 (바이브코딩 기준)

이 PRD는 두 가지 용도로 씁니다.

1. **심사용**: "기획부터 배포까지 소프트웨어 생애주기를 학생이 주도했다"는 근거 자료.  
2. **개발용**: Trae/Cursor/Claude 등 바이브코딩 도구에 **그대로 붙여넣어** 화면·기능을 생성하는 설계 원본.

원칙: **앱(React Native/Expo) 우선 → 동일 기능을 웹(Next.js)으로 확장**. 카메라·마이크 등 기기 기능(촬영·음성 통역)이 앱과 잘 맞으므로 앱부터 만든다. 앱·웹·백엔드를 **전부 TypeScript로 통일**해 코드·개념을 공유하고 바이브코딩 효율을 높인다. 모든 AI 호출(번역·통역·LLM·RAG)은 **클라이언트가 아니라 백엔드 서버**가 담당한다(아래 7장 보안 참조).

## 1\. 배경과 문제 정의

충남 지역 이주배경학생이 급증하면서 교실에서 다음 문제가 발생한다.

1. 다문화·이주배경학생은 한국어가 서툴러 국어 토의·토론 수업 참여가 어렵다.  
2. 국어 교과서 속 인물과의 대화·인터뷰형 학습에 접근하기 어렵다.  
3. 결과적으로 수업 참여도·성취도가 낮다.  
4. 외국인 학부모는 가정통신문을 이해하지 못해 담임과의 소통이 어렵다.

작년 사사과정(Note\&Quiz with AI)에서 OCR \+ LLM \+ DB \+ 배포 전 과정을 학생들과 완성한 경험이 있으므로, 올해는 그 역량 위에 **다국어 학습장벽 해소**라는 사회적 가치를 더한다.

## 2\. 목표 (연구목적과 1:1 연결)

| 연구목적(계획서) | 제품 목표 |
| :---- | :---- |
| 자기주도적 교육 형평성 실천 | 이주배경학생이 통역·번역으로 수업·과제에 스스로 참여 |
| 지능형 에이전트 기반 비판적 사고 | 교과서 인물 페르소나와 대화하며 문학적 맥락을 다면적으로 탐구 |
| 온디바이스 AI 기반 공학적 탐구 | Reachy Mini 로봇으로 인간-로봇 상호작용(HRI) 원리 체득 |
| 바이브코딩 통한 디지털 시민성 | 기획→구현→배포 전 과정 주도 \+ 개인정보·API 보안 실천 |

### 성공 기준(측정 가능)

- 이주배경학생이 통역 기능으로 토의에 1회 이상 발화 참여.  
- 교과서 1개 단원에 대해 OCR 번역 \+ 페르소나 대화 \+ RAG 질의가 동작.  
- 가정통신문 1건을 5개 언어로 번역 출력.  
- Reachy Mini가 음성 질문에 다국어로 1회 이상 응답(시연).

## 3\. 사용자(페르소나)

- **이주배경학생 (주 사용자)**: 러시아·중국·베트남·우즈베키스탄·카자흐스탄 가정. 한국어 읽기/말하기 보조가 필요.  
- **한국인 학생 (협력 사용자)**: 토의·토론 짝. 발화가 상대 언어로 통역됨.  
- **교사 (관리자)**: 교과서 자료 등록(RAG), 학생 계정 관리.  
- **학부모 (보조 사용자)**: 가정통신문 번역 열람.

지원 언어(번역·통역 대상): **러시아어, 중국어, 베트남어, 우즈베크어, 카자흐어** (+ 한국어 기준).

## 5\. 기능 명세 (화면·동작 단위 — 바이브코딩 입력용)

작년 보고서의 "화면별 명세" 방식이 바이브코딩에 잘 맞았으므로 동일 포맷으로 작성한다.

### 공통 — 메인 화면

- 상단: 인사("환영합니다, {이름}님"), 언어 선택 드롭다운(6개 언어).  
- 기능 버튼 6개: ①교과서 번역 ②실시간 통역 ③토론 친구 ④인물 인터뷰 ⑤가정통신문 번역 ⑥학습 기록.  
- 우선순위: 사용 빈도 높은 **통역·번역**을 상단에 배치.

### F1. 교과서 OCR 번역

- 카메라 촬영 또는 이미지 업로드 영역(미리보기 프레임).  
- '텍스트 추출' 버튼 → 서버가 OCR 수행 → 한국어 원문 표시(사용자가 오타 수정 가능).  
- '번역' 버튼 → 선택한 언어로 번역 표시. **원문/번역 좌우 또는 상하 병렬 표시**.  
- 모르는 단어 탭 → 단어 뜻 팝업(선택 기능).  
- 결과 저장 → 학습 기록.

### F2. 실시간 통역

- 화면 중앙 큰 마이크 버튼 2개: \[한국어 말하기\] / \[내 언어 말하기\].  
- 버튼 누르고 말하면: 음성→텍스트(STT)→번역→화면 표시 \+ 음성 재생(TTS).  
- 대화 로그가 말풍선(좌: 한국어 학생, 우: 이주배경학생)으로 누적.  
- 토의·토론 상황 가정: 두 사람이 번갈아 사용.

### F3. 토론 친구 (가상 한국인 학생)

- 주제 입력 또는 교과서 지문 선택.  
- 가상 한국인 학생 캐릭터가 **초등 눈높이 한국어**로 의견 제시 → 사용자가 반박/동의.  
- 사용자가 자기 언어로 입력하면 통역되어 토론 진행(언어 장벽 없이 토론 연습).  
- 목표: 학생 수가 적은 학교에서도 토론 가능(작년 구글독스의 'AI 토론 파트너' 계승).

### F4. 인물 인터뷰 (페르소나 에이전트)

- 교과서 단원/인물 선택(예: '흥부', '이순신', 동화 주인공).  
- 인물이 **1인칭**으로 답하는 인터뷰 챗봇. 한국어 \+ 선택 언어 병기 가능.  
- **프롬프트 엔지니어링 핵심**: 역할 부여 \+ 말투 \+ 시대/맥락 제약 \+ "교과서 근거 밖 내용은 상상이라고 표시".  
- 인터뷰 질문 추천 버튼 3개(예: "왜 그런 선택을 했나요?").

### F5. RAG (환각 억제)

- 교사가 단원별 교과서 텍스트를 등록 → 서버가 문단 단위로 분할·색인.  
- F3/F4 답변 시: 질문과 관련된 문단을 검색해 **LLM 프롬프트에 함께 제공** → 교과서 근거 기반 답변.  
- 답변 하단에 "근거: {단원/문단}" 표시(학생이 출처를 확인하는 디지털 리터러시 학습).  
- 초등 단순화: 벡터DB 미사용 시 키워드+임베딩 유사도 검색으로 대체 가능.

### F6. 로그인 / 학습 기록

- 이메일·비밀번호 로그인(**Supabase Auth**).  
- 학생별 저장: 번역 기록, 토론·인터뷰 대화, 즐겨찾는 단어.  
- AI가 저장된 기록을 바탕으로 복습 도움·간단 상담(예: "지난번 토론에서 이 표현을 어려워했어요").

### F7. 가정통신문 번역

- 가정통신문 사진/PDF 업로드 → OCR → 5개 언어 번역.  
- '핵심 요약'(날짜·준비물·제출기한) 자동 추출 표시.  
- 공유 링크/QR 생성(학부모 휴대폰에서 열람).

## 7\. 기술 스택 & 보안 (★ 가장 중요)

### 스택

- 앱(1차): **React Native (Expo)** \+ TypeScript  
- 웹(2차): **Next.js** (App Router) \+ TypeScript  
- → 앱·웹·백엔드 \*\*단일 언어(TypeScript)\*\*로 통일  
- 백엔드: **Supabase Edge Functions** (Deno/TypeScript) — API 키를 숨기는 서버 프록시 역할  
- 인증·DB·스토리지: **Supabase** (Postgres \+ Auth \+ Storage)  
  - 작년 Firebase 대신 Supabase 채택 이유: ① **RAG용 pgvector 내장**(별도 벡터DB 불필요) ② **관계형(SQL)** 데이터 모델이 본 PRD 구조에 적합 ③ \*\*RLS(행 수준 보안)\*\*로 개인정보 보안 학습에 유리  
  - 트레이드오프: 작년 Firebase 친숙도·재사용은 일부 포기(영재 사사과정에서 신규 학습 가치로 상쇄)  
- AI: OCR \= Google Cloud Vision / 번역·LLM \= OpenAI API(또는 동급) / STT·TTS \= 클라우드 음성 API  
- RAG: **Supabase pgvector**에 교과서 문단 임베딩 저장·유사도 검색 (DB 하나로 색인+검색 완결)

### 보안 원칙 (디지털 시민성 목표와 직결)

1. **API 키는 절대 클라이언트(웹·앱)에 두지 않는다.** 키는 서버 환경변수에만 두고, 웹·앱은 우리 서버의 엔드포인트만 호출한다.  
2. **작년 자료(.env·공유문서)에 노출된 Google Vision / OpenAI 키는 즉시 폐기(재발급)한다.** 노출된 키는 도용 위험이 있다.  
3. 학생·학부모 개인정보(이름, 얼굴, 상담기록)는 **동의 후 수집, 비식별화 저장**.  
4. 로봇 얼굴인식은 **로컬 저장·옵트인** 원칙.

이 1·2번은 학생들에게 "왜 키를 숨겨야 하는가"를 가르치는 한 차시 활동으로 만들 수 있다.

## 8\. 온디바이스 로봇 (Reachy Mini, 하이브리드)

- 하드웨어: **Reachy Mini** (Hugging Face, 오픈소스, 내부 Raspberry Pi 5 기반). 표정·머리 움직임으로 HRI 체험 최적.  
- 구성(하이브리드):  
  - **온디바이스**: 호출어 감지(wake word) \+ 음성→텍스트(STT) — "온디바이스 AI" 주제 충족.  
  - **API(서버)**: 무거운 다국어 번역·LLM·RAG 응답.  
  - **출력**: 스피커(TTS 음성) \+ 표정/움직임.  
- 시연 시나리오: 학생이 한국어/베트남어/카자흐어/중국어로 질문 → 로봇이 해당 언어로 응답 \+ 고개 끄덕임.  
- (정정) 온디바이스 경량 LLM은 **Gemma 3 / Gemma 3n**(2025, Pi·Jetson 구동)을 사용. 계획서의 "Gemma4"는 존재하지 않으므로 명칭 수정 필요.  
- 성능을 더 원하면 두뇌를 \*\*Jetson Orin Nano Super($249, 67 TOPS)\*\*로 교체하는 확장안 병기 가능.
